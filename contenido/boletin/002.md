Este número va de una idea: **meter en el contexto lo justo**. Ni todo lo que cabe, ni cualquier cosa que llegue de fuera.

## Lo que ha cambiado

**Ventanas de contexto enormes: no sustituyen a la recuperación.** Que un documento quepa en la [[glosario/ventana-de-contexto|ventana de contexto]] no significa que el modelo lo use bien. Cada token cuesta, añade latencia y compite por la atención con lo que sí importa. La recuperación sigue siendo la forma de elegir qué entra. Lo tienes en [[radar/2026-09-22-contexto-largo-no-sustituye-recuperacion]].

**La inyección de prompt llega por las herramientas.** Un agente que lee páginas web, correos o tickets mete en su contexto texto que no has escrito tú. Si ese texto trae instrucciones, el modelo puede seguirlas. Trata cada `tool_result` con contenido externo como no confiable y limita lo que el agente puede hacer después. Más en [[radar/2026-10-20-inyeccion-por-herramientas]] y en [[docs/seguridad/01-prompt-injection]].

## Un ensayo

[[blog/2026-09-28-el-contexto-es-un-presupuesto]]. La tesis: el contexto se gestiona como un presupuesto, con prioridades, y no como un cajón donde se echa todo por si acaso. Si te interesa la parte práctica, sigue con [[cursos/context-engineering/index]].

## Una receta: evals de regresión en CI

Cambias un prompt para arreglar un caso y rompes otros tres sin darte cuenta. La solución es ejecutar tu [[glosario/conjunto-de-evaluacion|conjunto de evaluación]] en cada *pull request*, como cualquier otro test.

```python title="evals/test_clasificador.py"
import json
from app import clasificar  # tu función que llama al modelo

UMBRAL = 0.9  # fíjalo a partir de la tasa que tienes hoy

def cargar_casos(ruta="evals/casos.jsonl"):
    with open(ruta, encoding="utf-8") as f:
        return [json.loads(linea) for linea in f if linea.strip()]

def test_tasa_de_acierto():
    casos = cargar_casos()
    fallos = [c["id"] for c in casos if clasificar(c["entrada"]) != c["esperado"]]
    tasa = 1 - len(fallos) / len(casos)
    assert tasa >= UMBRAL, f"Acierto {tasa:.0%}. Fallan: {fallos}"
```

Mide una tasa sobre todo el conjunto en lugar de exigir que pase cada caso: las respuestas de un modelo varían entre ejecuciones. Lánzalo solo cuando cambien prompts o código del modelo, para no gastar en cada commit. Los pasos completos, con la configuración de GitHub Actions, están en [[recetas/evals-de-regresion-en-ci]].
